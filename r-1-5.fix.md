# Full Synthesis (Rounds 1–5): Understanding, Gap Analysis, and the Parity Plan

## Part 1 — What Rounds 1–5 Actually Reveal (Level-5 Understanding)

Reading all five rounds together, one pattern repeats in every layer:

> **Klyro has the right architecture but incomplete wiring. Claude Code has a simpler architecture but complete wiring.**

Evidence per round:

- **R1 (Core Turn):** Klyro computes `allSafe` for parallelism… then ignores it. Detects stuck loops… then doesn't terminate. Has a verify gate CC lacks — its one fully-wired differentiator.
- **R2 (Streaming):** Klyro's adapter abstraction is *more* flexible than CC's Anthropic-native path, but has two correctness holes: silent delta drop (Anthropic) and 0-token usage on local providers (OpenAI-compat).
- **R3 (Permissions):** Klyro's policy engine is structurally comparable to CC's, but is missing exactly one node in the decision tree — the pattern cache — and that one missing node produces "80% of the UX difference users feel."
- **R4 (Context):** Klyro owns all the primitives (tokenizer, repo-map, compaction, accounting) but they're not wired into one path. No `cache_control` anywhere → CC is 30–40% cheaper per step. Two compaction paths → inconsistent behavior by entry point.
- **R5 (Persistence):** Klyro records *more* than CC (hashes, repairs, events, per-step checkpoints) but on *fragile* storage (non-atomic JSON, no lock, drift between trace and state). CC records less, durably.

So the diagnosis is not "Klyro is worse." It's: **Klyro is a richer machine with ~10 disconnected wires. CC is a leaner machine with every wire connected.**

**Where Klyro is stronger (protect these — CC structurally cannot copy them):**
- Verify gate → `classifyFailure` (env/pre-existing/introduced/flaky) → repair loop
- File-hash drift detection on every edit
- Event bus + `trace.jsonl` (answers "what did the runtime do at 14:22:34")
- Per-step replay (`fix-since-step`, re-verify with different command/model/policy)
- `POLICY_DENIED` as visible tool_result (model *knows* it was denied; CC's model doesn't)
- Provider-agnostic adapters (local models — CC is Anthropic-locked)

## Part 3 — The Plan to Make Klyro Work Like Claude Code

### Guiding principle
Don't clone CC. Adopt **CC's interactive floor** (fast, cheap, frictionless) while keeping **Klyro's autonomous ceiling** (verify, repair, replay). Concretely: make the default interactive session indistinguishable from CC in speed/cost/prompting, and keep verification as the opt-in/autopilot superpower.

### Phase 0 — Correctness & Feel (Week 1) — the six P0 fixes

| # | Fix | Location | Change | Effort |
|---|---|---|---|---|
| 1 | **Parallel tool execution** | `runtime.ts:604` | `if (allSafe) await Promise.all(finalizedCalls.map(runOne)); else` sequential. Map results back by call id to preserve transcript order. | ½ day |
| 2 | **Permission pattern cache** | `policy/approval.ts` + runtime call site | `ApprovalCache` keyed by `patternKey(call)` (e.g. `shell_exec:npm *`). Check **before** `approval.ask()`; store on "always" answers. | 1–2 days |
| 3 | **Stuck → terminate** | runtime stuck counter | Trigger 1: inject one "change approach" synthetic message. Trigger 2: interactive → pause & ask user; autopilot → abort with `stuck` status. | 1 day |
| 4 | **Tokenizer usage fallback** | runtime `message_end` handler | If `usage` absent → `estimateTokens()` for both sides, tag `estimated: true`. | ½ day |
| 5 | **Fix Anthropic silent drop** | `anthropic-adapter.ts:299-303` | Replace `if (!id) continue;` with degraded-stream event → runtime retries once or surfaces cleanly. Never drop silently. | ½ day |
| 6 | **Prompt caching** | Anthropic adapter request builder | Add `cache_control: {type:"ephemeral"}` to system block. **Prerequisite:** stabilize the prefix — move volatile telemetry (step count, recent calls) out of the system prompt to the end of the message list, or cache breaks every turn. | 1 day |

**After Phase 0 alone, Klyro matches CC on speed, correctness, and most of the cost gap.** These are all independent; ship as six small PRs.

### Phase 1 — Cost & Consistency Parity (Weeks 2–3)

7. **File-backed permission persistence (mode-aware)** — Persist "always-pattern" to `.klyro/settings.json` (project) + `~/.klyro/settings.json` (global) **in interactive mode only**. Autopilot stays session-only — R1 correctly noted you don't want unattended loops silently persisting allowances. This is a place to be *deliberately different* from CC.
8. **CC-parity approval keys** — `y / n / a (always-tool) / A (always-pattern)` in `TuiApprovalBridge`, wired to #2/#7.
9. **One compaction path, cheap-first ladder** — Delete `repl.ts` truncation. Single `context.compact()` triggered at ~92% window, all entry points. Ladder: (a) age old tool results → `{tool, exit_code, summary}` (free, CC's Band-5 trick), (b) drop oldest turns, (c) model summarization *only as last resort* — because Klyro's current compaction bills a model call where CC's is free. Explicit band budgets: system ~3k / memory ~800 / messages / aged-results ~400.
10. **Memory cap** — `memory-write.ts`: reject beyond ~2k tokens.
11. **Repair-loop accounting** — every repair turn increments `telemetry.recordCost` (`runtime.ts:534-578`).

### Phase 2 — Durability (Week 4)

12. **Atomic persistence** — temp-file + `rename` for state.json; append-only logs with per-line checksum; drop-partial-line recovery (steal CC's own trick). Defer SQLite unless this proves insufficient.
13. **Session lock file** — PID-based `lock`; `resume` refuses or explicitly takes over. Closes the two-process corruption finding.
14. **Transactional repair records** — repair-attempt + verification result written as one atomic append.
15. **Anthropic overflow recovery** — catch `request_too_large` at adapter boundary → typed event → compact (#9) → retry once. Closes the R4 MED finding of no top-level recovery path.

### Phase 3 — Surpass CC (ongoing)

16. Ship the commands only Klyro's state model enables: `klyro fix-since-step N`, `resume --verify-cmd`, `resume --model opus`, replay-with-stricter-policy. (Gate on Phase 2 — these need trustworthy state.)
17. Interactive error UX: surface malformed tool args in the TUI *before* execution (CC's better path) while keeping `_parse_error` forwarding for autopilot.
18. Interleaved tool_use streaming support (per-block-stop finalization instead of end-of-stream).

## Part 5 — Definition of Done

- Read+Grep+Edit turn ≈ slowest tool's wall clock, not the sum
- `bash(git *)`: one prompt per project lifetime (interactive); zero persistence (autopilot)
- Identical call ×3 → bounded termination with `stuck` status
- Ollama session shows non-zero estimated tokens; repair turns appear in cost totals
- Per-step cost within ~10% of equivalent CC session; cache hit rate visible in telemetry
- `kill -9` anywhere → clean resume; two instances on one session → refused
- **Regression gate: the verify → classify → repair loop must pass its full suite after every phase** — parity work may never break the differentiator

**Bottom line:** roughly one week of P0 work makes Klyro *feel* like Claude Code. Three more weeks make it *cost and survive* like Claude Code. Then Phase 3 delivers what CC can't: an agent that proves its work, replays from any step, and audits itself. Connect the wires that already exist first — then build what CC never can.
