# Round 6–10 Fix Plan — Klyro Multi-Agent Orchestration

## 1. Executive position (from r-6-10.fix.md)

Based on rounds 6–10, Klyro is not fundamentally weak; it is optimized for a **different execution model** than Claude Code:

- **Klyro:** one autonomous agent with verification, repair, structured errors, strong observability (event bus + trace writer).
- **Claude Code:** a dispatcher that coordinates multiple isolated workers with flexible tools and models.

The change is **not** "add more tools"; it is **building an agent orchestration layer** on top of Klyro's existing strengths. Target:

```text
Parent agent
  ├── dispatcher
  ├── task coordinator
  ├── merge manager
  └── final verifier

Child agents
  ├── separate context
  ├── restricted capabilities
  ├── optional model/budget
  ├── isolated workspace
  └── compact result returned to parent

Event bus
  └── lifecycle, status, cost, permission, verification, and failure events
```

> Do not remove Klyro's verification and event-bus features. Use them as the foundation.

## 3. Key contracts to honor

1. **Task record lifecycle:** `queued → running → succeeded | failed | cancelled | timed_out | blocked`.
2. **Capability intersection:** `effectiveTools = intersect(parentAllowedTools, agent.allowedTools ?? allTools, policyAllowedTools)`; deny-list wins.
3. **ScopedRegistry enforcement:** pass the child a `ToolRegistry` wrapper so both `toolDefinitions(registry)` and `registry.execute()` gate on the allow-set — zero runtime-loop changes.
4. **Model override must reach the provider:** `model: opts.parentContext?.model ?? opts.model` at the `CallRequest` build. A per-agent `model` must be honoured, else surface an explicit error.
5. **Non-blocking spawn with compact result:** `spawn_agent` returns a `ChildSummary` (not the child transcript).
6. **Cancellation chain:** parent abort → child `AbortController` fires → `cancelled` on the tree.
7. **Parent-only final verification** (revisit each child result; never trust blindly).

### Detailed: `spawn_agent` tool
- **Input:** `{ agent: string; task: string; cwd?: string; model?: string; timeoutMs?: number }`.
- **Resolve:** `ParentContextRef` from `ToolContext` (`parentTaskId`, `sessionId`, `cwd`, depth from runtime, `allowedTools`, `model`).
- **Behavior:** call `deps.agentBridge.spawnAgent(input, parent)`; on completion return `ToolResult<ChildSummary>`.
- **Safety:** depth guard (`childDepth > maxDepth` → `RECURSION_LIMIT`), unknown agent → `UNKNOWN_AGENT`.

### Detailed: CLI wiring
- `src/cli/run.ts`: parse `--agent` + `--max-depth`; resolve via `BUILTIN_AGENTS` → `AgentDefinition`.
- Build `RunOptions.parentContext = { depth: 0, maxDepth: <n>, allowedTools, model: <agent.model> }`.
- If no orchestrator is active and an agent is requested, construct a parent orchestrator and hand it to the runtime via `opts.agentBridge`.
