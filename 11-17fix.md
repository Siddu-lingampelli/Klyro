# Round 11–17 Fix Plan — Klyro Security, Persistence & Observability

## 1. Executive position (from r-11-17.md)

Rounds 11–17 audit **security, configuration state, and observability** — the layer beneath raw agent
capability. The decisive framing:

- **Klyro is stronger for code agents** (structured errors, trace writer, event bus, adapter
  abstraction), but **loses** on UX polish that looks cosmetic yet is high-severity in practice:
  transient permissions, coarse transport retries, a missing context-file trust gate, and no
  MCP-through-the-full-stack security.
- **Critical design constraint the audit demands:** don't import Claude Code's ecosystem *and*
  its weakest security seam. Klyro must route **every** `mcp__*` call through `PolicyEngine` **and**
  `secret-redactor` **and** the event bus. If MCP tools bypass Klyro's layers, the ecosystem win
  becomes a security regression.
- **Default deny, opt-in expand.** Network off; MCP servers allowlisted per-tool; plugins sandboxed.

> Do not soften Klyro to match CC's frictionlessness. Beat CC on the dimensions Klyro can own
> (traceability, policy enforcement, trust gates) while closing its HIGH-severity gaps
> (re-prompt forever, no transport backoff, context-file injection).

## 3. Key contracts to honor

1. **Default deny.** Network off until `network.enabled` + `allowedDomains`. MCP tools denied by
   `PolicyEngine` unless allowlisted per-server. Plugins sandboxed by default.
2. **Full-stack MCP.** Every `mcp__*` call → `PolicyEngine` (allowlist) → Zod input validation →
   `AbortSignal`-bound timeout → `secret-redactor` → event-bus emit. Registration must not bypass
   Klyro layers.
3. **Schema validation, never trust.** MCP tool input schemas converted to Zod via
   `zod-from-json-schema` and validated at the boundary.
4. **Redaction on the way out.** Any MCP/resource result is redacted before reaching the model or
   the trace.
5. **Retry telemetry, not retry secrecy.** `withRetry` hides retries from the model & default TUI,
   but emits `provider.retry` events and writes `retry` entries to `trace.jsonl`. CC cannot answer
   "how flaky was my week"; Klyro must be able to.
6. **Trust gate on context files.** On unknown/changed hash: show a diff, require approval, emit
   `context.trust_prompt` on the bus.
7. **Persistent grants survive resume.** `grants.json` + `[p] always (persist)` +
   `klyro permissions` CLI — beat CC's in-session-only "always allow."

## 4. Priority 0 — security-critical (must land before MCP is usable)

### P0.1 — Policy engine gate  ✅ foundation present (needs extension)
- Extend the existing `resolveCapabilities`/`ScopedRegistry` model into **call-time** policy.
- `src/agent/policy.ts` (new): `PolicyEngine` evaluates a `mcp__*` tool call against a
  per-server `allowTools`/`denyTools` allowlist; deny-list wins.
- Hook: `ScopedRegistry.execute` checks `PolicyEngine` before delegating to the parent registry.
- Non-negotiable: if the policy check is bypassed, the MCP loader refuses to register the tool.

### P0.2 — Secret redactor  (not present)
- `src/agent/redactor.ts` (new): scan tool results for secret-like patterns (tokens, keys,
  high-entropy strings) and redact before they reach the model or the trace writer.
- Applied at the MCP tool wrapper boundary (see §5).

### P0.3 — Context-file trust gate  (not present)
- `src/agent/context-trust.ts` (new): hash context files; on unknown/changed hash show a diff,
  require approval, emit `context.trust_prompt` on the bus.
- Closes the **shared HIGH flaw** (context-file injection) that Klyro and CC both leave open.

### Detailed: MCP registration (the non-negotiable part)
```typescript
// registration must not bypass Klyro layers
for (const t of await client.listTools()) {
  registry.register({
    name: `mcp__${server}__${t.name}`,
    description: t.description,
    inputSchema: zodFromJsonSchema(t.inputSchema),   // validate, don't trust
    execute: async (args, ctx) => {
      // 1. PolicyEngine already gated this upstream in runtime.ts
      // 2. emit tool_call.start on the bus
      const res = await client.callTool(t.name, args, ctx.signal);
      // 3. redact before it reaches model OR trace
      return secretRedactor(res);
    },
  });
}
```

## 8. Verification plan

```bash
npx tsc --noEmit
npm test
```

Unit expectations:
- **PolicyEngine**: deny by default; allowlist permits; deny-list overrides allowlist; MCP tools
  without an allowlist cannot execute.
- **redactor**: secret-like strings in results are redacted before return.
- **context-trust**: changed hash → emits `context.trust_prompt` and blocks until approved;
  known hash → passes.
- **withRetry**: 429/5xx → `provider.retry` emitted, retries up to `maxAttempts`, then throws;
  fatal/auth errors → no retry, no emit; `AbortSignal` aborts the whole attempt sequence.
- **MCP registration**: tool appears as `mcp__<server>__<tool>`; executing it with a disallowed
  allowlist returns a policy-denied error before any call leaves the process.

## 9. Non-goals (kept out of scope intentionally)

- Full plugin-system rewrite (only the default-sandbox enforcement).

## 10. Implementation order

1. `src/agent/policy.ts` — `PolicyEngine` (allow/deny per server) + wire into
   `ScopedRegistry.execute`. **Blocks everything else.**
2. `src/agent/redactor.ts` — `secretRedactor`; apply at the MCP call boundary.
3. `src/agent/context-trust.ts` — hash + gate + `context.trust_prompt` event.
4. `src/mcp/config.ts` + `src/mcp/client.ts` — loader + client; mirror `.mcp.json`.
5. `src/mcp/registry.ts` — register tools as `mcp__<server>__<tool>` through policy + redactor + bus.
6. `src/agent/retry.ts` — `withRetry` wrapping the adapter, below the step loop; emit
   `provider.retry`; silence in default TUI, persist in `trace.jsonl`.
7. Tests: policy (allow/deny/none), redactor, context-trust (changed-blocked, known-passes),
   withRetry (429 retry, fatal no-retry, abort).
8. `npx tsc --noEmit` + `npm test` green; commit the P0+P1 security-critical slice.
